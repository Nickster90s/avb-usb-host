# avb-usb-host — read this before touching the USB gateware

Amaranth/LUNA source for the USB device used by the Dante transmitter. **The
synthesised product of this repo lives in a different repo**: the two 22k-line
`rtl/usb_avb_subsystem{,2}.v` files in `/home/lisp/DANTE/FPGA/dante-usb` are
machine output from here, regenerated by that repo's
`tools/gen_usb_subsystem.py`. Nothing in this repo is built by `dante-usb`'s
`build.sh`; the `.v` files are committed artifacts.

This file holds the findings that are expensive to rediscover. Long-form
reasoning stays in the source comments, which in this project are the record of
what was measured.

```sh
.venv/bin/python           # the environment; amaranth + LUNA + usb_protocol
```

## Regenerating, and the one rule about it

```sh
# from the dante-usb checkout, not here:
tools/gen_usb_subsystem.py main      # -> rtl/usb_avb_subsystem.v   1209:eab1
tools/gen_usb_subsystem.py backup    # -> rtl/usb_avb_subsystem2.v  1209:eab2
```

`VARIANTS` in that script holds the only differences between the two: module
name, product name, serial and PID. It exists because `usb_avb_subsystem2.v`
was once a **mechanical rename** of the first file — two differing lines — so
both buses advertised Main's PID with Backup's product string and Backup's
serial. Regenerate both, always, or they drift again.

**Re-emitting the descriptors moves both ULPI eye centres.** The descriptor ROM
is synthesised logic, so changing it re-rolls placement. The sequence is not
optional:

1. regenerate both variants
2. rebuild the gateware (`./build.sh` in `dante-usb`)
3. `tools/tapsweep.py --phy main` **and** `--phy backup`
4. pin the winning taps
5. rebuild

The eye is currently settled by a PLL phase, not by the tap: `USB_PHASE_DEG=333`
on `cd_usb` only, with IDELAY tap 31 on both PHYs. At phase 0 even tap 31 — the
hardware maximum — leaked 1.28% of real audio. See `dante-usb`'s CLAUDE.md.

## Interface numbering depends on an environment variable

`usb_descriptors.py:123`:

```python
playback_only = os.environ.get("PLAYBACK_ONLY", "1") == "1"
```

**It defaults to 1, so the capture interface is not emitted** and the shipping
device has:

| | playback-only (the default) | `PLAYBACK_ONLY=0` |
|---|---|---|
| IF0 | AudioControl | AudioControl |
| IF1 | playback, OUT | playback, OUT |
| IF2 | *(absent)* | capture, IN |
| next free interface | **2** | **3** |

So any new interface's number is `2 if playback_only else 3`. Compute it once
and pass it around; do not write the number twice.

Capture is dropped on purpose and the reason is measured: macOS opens the device
full-duplex and runs capture alongside playback on one IO work loop, and EP 0x82
delivers no real audio yet, so it starves the loop → Audio IO Overload →
silence at ~2 s. Linux never hit it because `aplay` opens playback-only.

Endpoints in use: **0x01** iso OUT (audio), **0x81** iso IN (feedback),
**0x82** iso IN (capture stub). **0x83 is free.**

## The control endpoint, and what it does to class requests

`requesthandlers.py`, verbatim:

```python
with m.Elif(setup.type == USBRequestType.CLASS):
    # Claim ALL class requests — this device owns the audio class
    # space; unknown ones fall to the Default stall below.
    m.d.comb += interface.claim.eq(1)
```

**So every class request is claimed by the audio handler and anything it does
not recognise is STALLed.** A second class on another interface — HID, for
instance — never sees its own requests. HID's GET_REPORT is request `0x01`,
which is also Audio's CUR, so the request code cannot tell them apart: the
discriminator is `setup.index`, the interface number. Narrow the claim by
interface, not by request code.

`SET_INTERFACE` is blacklisted out of LUNA's standard handler
(`usb_avb_subsystem.py:235`) and handled here instead. It zeroes **both**
altsetting registers before its `Switch`, so a `SET_INTERFACE` aimed at any
interface other than 1 or 2 — including IF0 — clears both and restores neither.

> **Corrected 2026-11-07:** this was reported as an audio-killer. It is not, in
> the shipping design. `output_interface_altsetting_nr` and
> `input_interface_altsetting_nr` have **no consumer in
> `usb_avb_subsystem.py`** — the only reader anywhere is
> `usb_utmi_top.py:309`, a bench top. LUNA's isochronous endpoints gate
> themselves. So it is a latent wart that becomes a real bug the moment those
> signals are wired up, not a reason audio would stop today. Verified by
> grepping every `.py` in `gateware/`.

`interface_settings_changed` likewise has no consumer outside this file.

## Amaranth traps recorded here the hard way

- **`m.d.sync` is NOT the usb domain in `requesthandlers.py`.** Hence the
  `StreamSerializer`'s explicit `domain="usb"` and the `DomainRenamer` around
  the decoder in `usb_avb_subsystem.py`. Use `m.d.usb`.
- **An `m.d` statement mid-chain breaks an `If`/`Elif` chain** with "Elif
  without preceding If". If you need a registered value inside one, assign it
  *before* the chain starts.
- `cur_rate` is a combinational `Mux` deliberately. An attempt to register it
  "off `cd_usb`'s critical path" failed twice on both traps above — **and the
  premise was never measured.** nextpnr prints the critical path in the build
  log; look it up there before rewriting anything for timing.

## `usb_protocol` has no HID emitter

`emitters/descriptors/` ships `standard`, `cdc`, `uac1/2/3`, `midi1/2`,
`microsoft10` — and no `hid`. `InterfaceDescriptorEmitter` and
`EndpointDescriptorEmitter` do exist, so the standard interface and endpoint
descriptors emit normally; the HID class descriptor (type `0x21`) and the report
descriptor have to go in as raw bytes. LUNA's `GET_DESCRIPTOR` ignores the
recipient and `wIndex`, so a raw descriptor keyed by type and index is served
without a custom handler.

## What the gateware costs the other repo

Cells added inside the USB hierarchy are pulled into `dante-usb`'s
`floorplan_usb.py` USB region, because it matches on cell names and walks net
connectivity. That region is on the edge of feasibility:

| cells in `usb_fp` | result |
|---|---|
| ~1385 (light mode, the default) | places, HeAP 49–80 s |
| ~3109 (full box) | **HeAP hangs, 8 seeds out of 8** |

So check the `[floorplan_usb] USB:` line in the build log after any change here.
Also: `fifo_depth=256` on the bridge FIFO is forbidden with hardware evidence —
the project nominates the upstream `FIFO_DEPTH` as the trade instead.
